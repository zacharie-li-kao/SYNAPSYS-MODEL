# The modelling module

The modelling module simulates a synaptic device with a physical model, extracts the parameters of that model from a characterisation suite, and uses them to simulate arrays of devices and spiking networks. The window has a left panel, called Synapse Controls, that is shared by all the tabs, and four tabs: Simulation, Model Fitting, Network and SNN. Before any file is loaded the simulated device uses a set of default parameters, and the box Synapse State at the bottom of the left panel says whether the parameters are those defaults or come from a loaded file.

The Simulation tab shows the conductance of a single device while pulses are applied (Figure {model_sim}). The Operation Mode is Potentiation (LTP) or Depression (LTD), and a depression can be driven optically or by voltage pulses. The sliders set the intensity (0.1 to 100 mW/cm²), the wavelength, the pulse width (10 to 500 ms), the rest between pulses and the number of pulses (1 to 50). The wavelength range follows the fitted spectral response when a model is loaded. Apply Potentiation, which reads Apply Depression in depression mode, runs the pulse train and draws the conductance above the wavelength response curve of the device, with the light pulses as a dashed line and the current wavelength marked on the curve. When a fitted spectral response is loaded, the wavelength decides if a pulse potentiates or depresses (a positive lobe of the curve potentiates and a negative lobe depresses), so the requested operation mode cannot override it. The Synapse State box reports the branch that was taken when it differs from the one that was requested. Auto Demo runs a fixed sequence at several wavelengths, and Reset brings the device back to its initial state.

![The Simulation tab after thirty pulses at 365 nm with a loaded model.](figures/model_sim.png)

The Model Fitting tab starts from a characterisation suite. Load Experimental Model opens a JSON file, which is either a suite written by the characterisation tool or the data converter, or a fitted model saved earlier. For a suite the parameters are extracted at once, and the text lists them together with the quality of each fit (Figure {model_fit_loaded}). The parameters are G_min, G_max and their ratio, the exponents α and β of the potentiation and depression nonlinearities, the rates A_peak and B_peak, the peak wavelength and width of the spectral response, and the retention time constant. A parameter that could not be extracted from the file is not hidden: it is followed by a tag that says that it is missing from the file, that its fit failed, or that it is a default and was not measured, and a block at the end of the text lists everything that was not measured. A fit with R² below 0.8 is tagged POOR. A_peak and B_peak depend on α, whose uncertainty is reported with them, and the rates k_A and k_B printed under them do not, so that devices are better compared on k. Save Fitted Model writes the model to a JSON file that Load Experimental Model can read again.

![The Model Fitting tab after loading the suite exported by the data converter.](figures/model_fit_loaded.png)

Once a model is loaded, the button Run Fitting Demo is renamed Run Fitting. It first asks about the number of peaks of the wavelength response when this was fitted (Figure {model_peaks}). The dialog gives the number of peaks that was detected, with their wavelength and their type, and the fit quality. Use automatic keeps the result, and forcing one, two or three peaks refits the spectral response with that number. A forced refit replaces the simulated device, and a network or an SNN that exists then has to be initialised again. The fitting window that follows draws the data and the fit for the wavelength response, the nonlinearity, the retention, the dynamic range, the STDP window and the SRDP response (Figure {model_fitplots}). It has Save Plot and Close Window buttons, and it can be enlarged. Without a loaded model, Run Fitting Demo generates a synthetic suite, fits it and compares the fitted values with the values used to generate it. It does not change the simulated device.

The Network tab simulates an array of devices. Choosing Network as the Target in the left panel adds the size of the array (rows, columns, with quick buttons from 3 × 3 to 10 × 10), the device variability in per cent and a list of spatial patterns: bars, diagonals, a cross, corners, a checkerboard, a circle, a duck, a thumb up, a raised fist and others. Load Excel Pattern adds a custom pattern from an Excel file, which is then resized to the array. The network mode is rate-based, which applies the patterns to the devices directly, or spiking, in which the synapses learn with STDP. Changing the mode discards the existing network. Initialize Network builds the array with the loaded parameters, and with the variability given in the left panel, so that every device is slightly different. The Apply button of the left panel, which reads Apply Pattern to Network when the target is the network, then applies the selected pattern for the chosen number of pulses with the rest between them, and the tab shows the conductance of every device next to the intensity of the last pattern (Figure {model_net}). If no network exists the tool offers to initialise one. Rest (500ms) lets the array relax, Show Evolution opens the window with the successive states (Figure {model_evolution}), and Reset Network brings the array back to its initial state. Run Network Demo initialises an array and applies four patterns of five pulses each at the potentiation peak of the loaded model.

![The Network tab after twenty pulses of the pattern Duck on a 10 × 10 array at 365 nm.](figures/model_net.png)

![The window opened by Show Evolution.](figures/model_evolution.png)

The SNN tab simulates a spiking network with an input layer and a hidden layer, whose synapses are the devices of the model (Figure {model_snn}). The fields are the number of input neurons, the number of hidden neurons, the input firing rate and the duration of the simulation, and the checkbox Enable STDP Learning switches the weight update on. The input spikes are drawn from a Poisson process. Run SNN Simulation prints the setup in the output box and draws the input spikes, the hidden spikes and the weights before and after the run. The STDP parameters are the fitted ones when the loaded suite contains an STDP measurement, and the documented defaults otherwise, and the output box says which of the two is used. A warning is written in the output box when the number of input neurons is too small for the device variability. Reset SNN clears the network, its results and the output.
